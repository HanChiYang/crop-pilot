# 資料庫與 API 設計審查

1. 讀取專案指引、已確認需求、資料庫設計和 API 契約。確認提問涉及資料庫、API 請求或回應、畫面用語，或跨層行為。若同一名稱在多層出現，依使用者指定的範圍判斷是否改名或補寫對應。
2. 按變更內容檢查欄位型別、是否必填、預設值、唯一性、外鍵、刪除行為與資料驗證。對狀態變更核對允許值與轉換條件。對登入或授權變更，沿著帳號查找、身分驗證、角色與資源擁有者檢查核對責任。
3. 將已確認的決定寫入對應的設計文件。逐欄維護規格表，分開約束與描述。同步更新受影響的 ER 圖、關聯說明、流程、請求及回應範例。涉及對外契約時，依專案的契約來源更新 OpenAPI。資料庫與 JSON 使用不同名稱或值時，明列對應。
4. 檢查是否還有舊欄位或舊流程的引用。回報已更新的設計、待決事項和目前實作的差距。設計審查以可供確認的文件為產出。程式、migration、契約生成與執行驗證依使用者授權的工作階段進行。

在 CropPilot，先讀 `AGENTS.md`，以 `docs/design/` 下的資料庫和 API 文件及 `docs/openapi/openapi.yaml` 為設計來源。若進入 migration 實作，沿用專案的 EF Core SQL 審查流程。
