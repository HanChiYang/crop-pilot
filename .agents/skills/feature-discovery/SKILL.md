# 需求訪談與功能切片

1. 先讀目前專案的協作指引、開發進度及相關需求。延續已確認的決定。若已有設計審查記錄，對照畫面、流程與待決事項，找出這輪真正要決定的問題。
2. 從使用者、操作情境和希望完成的結果開始。沿著實際流程釐清入口、前置條件、關鍵操作及成功後看見的結果。每次只問一個會影響範圍或行為的問題。已有答案的項目直接沿用。參考產品的做法列為候選，等使用者確認後才列入需求。
3. 選出一條最小且可完整操作的流程。寫清楚首版涵蓋的使用者、裝置和操作，分開記錄後續項目與待決事項。把必要的正常和失敗情況寫成能觀察到結果的驗收條件。
4. 按專案既有格式整理成需求文件，連回相關設計稿或進度記錄。把尚未確認的內容標為提案，讓使用者逐項確認。需求與驗收條件確認後，依專案指引交接給 UX。以使用者指定的工作階段為本輪終點。

在 CropPilot，從 `AGENTS.md` 找到目前進度、需求訪談方式和 UX 審查記錄。用 `docs/requirements/` 裡已確認的切片作為格式參考，並在交接時記下對應的桌機 Figma 流程。
